# 検索構成ごとの正答率の実測（2026-08-04）

「意味検索の上に、質問の書き換えや選び直し（リランク）を足すと精度は上がるのか」を確かめるために測った記録です。
結論を先に書くと、この規模では意味検索だけで満点に届き、上乗せの工夫はどれも改善しませんでした。

## 測り方

- **文書**: 介護法人を想定した架空の社内文書 12本 / 42箇所（`corpus.mjs`。この実測のために書き下ろし）。
  就業規則、経費精算規程、育児介護休業規程、テレワーク細則、操作マニュアル、感染症対応マニュアル、拠点別ルール2つ、議事録2本など。
  わざと言葉が重なるように作っています（「休暇」が4文書に出る、2つの拠点に同じ見出しがある、など）。
- **質問**: 職員が実際に打ちそうな口語の質問 28問（「有休って何日もらえるんだっけ」など）と、文書に答えが無い質問 4問（`questions.mjs`）。
  答えが無い4問には、似た言葉が文書中にあるものを選んでいます。
- **判定**: 検索は、正解の箇所が上位に入ったか。回答は、必要な事実（「10日」「12,000円」など）を含むか。答えが無い4問は、断れたか。
- **モデル**: 埋め込みは `gemini-embedding-001`（768次元）、回答生成は `gemini-flash-lite-latest`。
  生成は下位のモデルで測っているので、結果は低めに出る側の条件です。

## 結果1: 検索構成の比較（答えのある28問）

| 構成 | 正解を拾えた | 1位が正解 |
|---|---|---|
| A 言葉の重なりだけ（埋め込みなしの軽量構成） | 19/28 (68%) | 14/28 (50%) |
| B 意味検索 | 28/28 (100%) | 28/28 (100%) |
| C 意味検索 + 質問の書き換え | 28/28 (100%) | 28/28 (100%) |
| D 意味検索 + AIによる選び直し | 28/28 (100%) | 28/28 (100%) |
| E 意味検索 + 言葉の重なりの併用（RRF） | 24/28 (86%) | 20/28 (71%) |

## 結果2: 回答まで通したとき

| 構成 | 正しく答えた | 答えの無い4問を断れた |
|---|---|---|
| B 意味検索 | 28/28 | 4/4 |
| D 意味検索 + 選び直し | 28/28 | 4/4 |

## 結果3: 文書の切り方（意味検索 + AI回答で固定）

| 切り方 | 正しく答えた | 断れた |
|---|---|---|
| 条・見出しで切る（42箇所、アプリの既定） | 28/28 | 4/4 |
| 文書まるごと1つ（12箇所） | 27/28 | 4/4 |
| 300字ごとに機械的に切る（18箇所） | 28/28 | 4/4 |

## 分かったこと

1. 意味検索にした時点で頭打ちになり、上乗せの工夫には伸びしろがありませんでした。併用（E）はむしろ下がりました。順位の粗い検索を混ぜると、良い候補が押し下げられるためです。
2. 言葉の重なりだけの構成は弱く、1位が正解なのは半分でした。「有休って何日？」に議事録の手当の記述を返すような外し方をします。
3. 答えが無い質問を断る力は、選び直しを足さなくても、回答生成の指示文だけで足りていました。
4. この規模では、文書の切り方は結果にほとんど影響しませんでした。

## この実測の限界

- 文書は自作の12本42箇所です。実際の社内文書はもっと長く、表記が揺れ、スキャン由来の崩れも混じります。数百箇所規模は測っていません。
- 埋め込みは Gemini で測っています。アプリの本番構成で想定している Cloudflare Workers AI（`@cf/baai/bge-m3`）は別のモデルなので、同じ数字になるとは限りません。
- 規程の新旧版が混在するケースは測っていません。
